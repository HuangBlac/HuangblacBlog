# 数学系转人工智能需要选计算机相关课程吗？

要选。选到什么程度，要看你准备往哪里转。

我在信息与计算科学专业待了几年。课表里有数分、高代、泛函和微分方程，电脑里也装过 MATLAB、R、C 和 Python。以前我觉得，把公式翻译成代码，程序能跑起来，大概就算学会编程了。

后来我用 AI 做过一些项目，大类越写越大，功能全堆在一起，硬编码、没测试、没注释这些坑挨个踩了一遍。程序确实跑起来了，我却不敢随便改它。有一次我才弄清楚，自己在浏览器里打开的 `localhost` 只属于这台电脑，想让别人访问，还得有一台真正对外提供服务的机器。

这种尴尬很有用。它让我知道，数学系学生补计算机课，并不是为了在成绩单上拼出第二个专业。你需要补到什么地方，取决于以后准备解决什么问题。

## 留在数院做人工智能

我把这条路叫作小转。

人还在数学、计算数学或统计的训练体系里，研究对象换成了机器学习、科学计算和 AI4Science。优化算法为什么收敛，神经网络怎样逼近函数，PINN 和 neural operator 解微分方程时误差从哪里来，这些问题依然需要分析、概率、数值方法和微分方程。

走这条路，数学课仍然占大头。数分和高代要学稳，后面继续补实变、泛函、概率、随机过程、数值线性代数、数值分析、优化与微分方程。课程不可能全部修完，可以跟着具体问题选。研究 PINN，会频繁碰到偏微分方程、优化和数值误差。研究 diffusion model，概率与随机微分方程会更常出现。做大模型推理，又会遇到矩阵计算和低秩近似。

计算机课也得选，只是不用把计院培养方案完整抄一遍。我会优先选程序设计和数据结构。前者让你知道一段能维护的程序怎样组织，后者让你理解数据放在哪里、一次计算大概要付出多少时间和内存。Git、命令行和基本测试不一定有正式课程，却应当跟着项目一起学。反而那些计算机组成原理是次要的，反正这对于你是否能把问题求出了帮助较少。毕竟这些也实际上没有出现在你的培养方案里面。

找导师时，可以直接看数院老师近几年的论文题目。出现 optimization、scientific machine learning、PINN、neural operator 或 deep learning theory，再去问能否旁听组会，有没有适合本科生复现的小问题。邮件里写清楚自己上过哪些课、做过什么程序。只说“我对人工智能很感兴趣”，老师很难判断该把什么交给你。

小转的优势很朴素。你能读懂公式，也愿意追问算法为什么有效。代码至少要把这些想法做出来，让实验能够重复，让别人看得懂。

## 去计算机学院做人工智能

我把这条路叫作大转。

这里会更关心模型能不能训练、系统能不能稳定运行，以及方法放到真实数据上有没有效果。数学基础仍然有用。模型不收敛、loss 变成 NaN、论文里的理论与实验对不上时，读得懂矩阵求导、概率不等式和优化条件，总会多一种排查办法。

代码要求也会明显提高。数据结构与算法、Python 或 C/C++ 这些课程是类似于数分高代的基础课程，甚至数院也会安排。后面学多少计算机组成原理、操作系统和网络，要跟着方向走。想做算法研究，可以把时间更多放在机器学习、优化和实验复现上。除非想做 AI infra 或 ML sys，系统课程绕不过去，这个跨度也确实很大。我自己离这块还远，不打算装成过来人给一张包治百病的课表。

数学系学生在大转时容易高估自己的数学优势。企业和实验室不会只看你学过泛函分析，他们会看你能不能处理数据、复现实验、读懂已有代码，再把结果讲清楚。数学能帮你解决其中一些难题，其他部分仍得亲手补上。

## 选课之前先找一个问题
让我们说回选课本身，课程名称很容易让人产生完成感。

机器学习、深度学习、计算机视觉、自然语言处理排在一起，像是修完就能进入人工智能。但要想真正明白，还是得去动手去做。

如果想走 AI4PDE，可以先复现一个最简单的 PINN，再用有限差分做一个基线。两边的误差、速度和训练过程摆出来，你很快会知道自己缺的是偏微分方程、数值分析、优化，还是 PyTorch 的基本操作。

如果想走现在流行的大语言模型LLM算法类，可以从线性回归、决策树或者公开数据集Iris鸢尾花开始。把数据清洗、训练、验证和结果解释完整走一遍。卡在复杂度，就回去补数据结构。看不懂训练过程，就补概率统计和优化。程序一改就坏，再去学测试和软件工程。

## AI工具可以用，而且应该早点用

而且相比于数院学生固有的选课思维，计算机这样的工科更关键的在于动手实践。talk is cheap,show me your code就是最实际的讲法。

使用 Codex、Claude Code 之类的工具当然确实是如虎添翼，环境配置、报错排查和基础代码生成，它们能省掉很多毫无意义的折腾。毕竟这些被称为“偶然复杂度”的部分会迅速榨干你的热情，所谓从入门到放弃就是我在前AI时代无数次试图入门但最终放弃的原因。

但代价是什么呢？AI 可以在几分钟里写出几百行代码，但你往往也看不懂它。项目规模一大，今天省下来的时间会变成以后不敢修改的技术债。

用 AI 学编程时，最好让它一次只改一小块。改完要求它解释文件之间怎样调用，再给关键函数补测试。每次能运行就提交一次 Git。你至少要说清楚输入从哪里来，经过哪些函数，最后写到哪里。做到这里，AI 才像一位随时能问的助教，而不是一个替你交作业的人。

## 数学课也别急着扔

很多数学系学生一准备转 AI，就想把培养方案里的数学课全部判成无用。这个决定通常太早。

线性代数、概率统计、优化和微分方程会直接进入不少 AI 方向。实变与泛函未必每天出现，准确来说，在很多人眼里这就没什么用。但意识到纷繁复杂的所谓人工智能最终还是在处理函数空间、收敛和逼近，就是站在山顶，一览众山小。

课程能不能转化成优势，还要看你是否把它接到论文、代码和具体问题上。

以及，你不是真空之中的理想学习者，你的保研和读研也要考虑。AI4Science、理论机器学习、优化和计算数学大多需要更长的训练。本科阶段去选一堆计算机课程可能会影响保研，选择可能会更少。

我自己的做法也谈不上标准答案。我还在数院，方向偏 AI4PDE，写代码时依然经常欠债，也没有资格替别人保证就业结果。我能确认的只有一件事。转 AI 不需要等到所有课程学完以后才开始。

先找一个小问题，把项目建起来。公式不懂就查数学，代码不懂就补计算机。做到一半去问老师，做完以后把它放到 GitHub，再看下一个问题。

选课会逐渐变得清楚。人也会慢慢知道自己更愿意在哪种问题上耗时间。

至于最后去了数院、计院，还是某个名字更长的新学院，都可以以后再决定。

好好生活。祝你幸福 desuwa。
